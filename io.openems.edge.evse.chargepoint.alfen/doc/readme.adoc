= Alfen Eve Chargepoint Component

This component provides integration for Alfen Eve series wallboxes (NG9xx platform) via Modbus TCP.

== Supported Models

* Alfen Eve Single S-line
* Alfen Eve Single Pro-line
* Other Alfen NG9xx series wallboxes with Modbus TCP support

== Prerequisites

IMPORTANT: The charging station requires the license key for "Active load balancing" before the Modbus slave functionality can be enabled.

1. Acquire the "Active Load Balancing" license from Alfen
2. Enable "Active Load Balancing" via the Alfen Service Installer application
3. Select the "Energy Management System" option in the Active balancing -> Data source field

== Connection Settings

* **Protocol**: Modbus TCP
* **Default Port**: 502
* **Default Modbus Unit ID**: 1 (some installations may use 200)

== Modbus Register Mapping

The following registers are implemented based on the Alfen Modbus Slave TCP/IP documentation:

=== Measurement Registers (Read-Only)

[cols="1,1,2,3"]
|===
|Address |Type |Unit |Description

|306-311
|Float32 x3
|V
|Phase voltages (L1, L2, L3)

|320-325
|Float32 x3
|A
|Phase currents (L1, L2, L3)

|344-347
|Float64
|W
|Active power

|374-377
|Float64
|Wh
|Total energy delivered
|===

=== Status and Control Registers

[cols="1,1,2,3"]
|===
|Address |Type |Access |Description

|1201-1205
|String (5 regs)
|Read
|Charging state according to IEC 61851-1 (A, B, C, D, E, F)

|1210-1211
|Float32
|Read/Write
|Maximum current limit in milliampere (0-32000 mA)

|1215
|Uint16
|Read/Write
|Phase configuration (1 = single phase, 3 = three phase)
|===

== Charging States (IEC 61851-1)

[cols="1,3"]
|===
|State |Description

|A
|Not connected - No vehicle plugged in

|B
|Connected, not ready - Vehicle connected but not ready for charging

|C
|Charging - Active charging session

|D
|Charging with ventilation - Charging with ventilation required

|E
|Error - Charging station error

|F
|Not available - Charging station not available
|===

== Simulation Mode

Simulation mode allows testing without real hardware. When enabled, the component uses an internal IEC 61851-1 state machine instead of communicating with a physical charger.

=== Configuration

[source,json]
----
{
  "id": "evseChargePoint0",
  "alias": "Alfen Simulator",
  "enabled": true,
  "simulationMode": true
}
----

=== Control Channels

[cols="1,1,2"]
|===
| Channel | Type | Description

| `SimulationMode`
| Boolean
| Indicates simulation mode is active

| `SimulatePlugIn`
| Boolean (R/W)
| Set to `true` to simulate plugging in a vehicle

| `SimulateUnplug`
| Boolean (R/W)
| Set to `true` to simulate unplugging a vehicle

| `SimulateError`
| Boolean (R/W)
| Set to `true` to trigger an error state

| `SimulateClearError`
| Boolean (R/W)
| Set to `true` to clear the error state
|===

=== State Transitions

* *A → B*: `SimulatePlugIn` - Vehicle connects
* *B → C*: Automatic when `SetChargingCurrent` > 6000 mA
* *C → B*: `SetChargingCurrent(0)` - Stop charging
* *B → A*: `SimulateUnplug` - Vehicle disconnects
* *Any → E*: `SimulateError` - Error condition
* *E → A*: `SimulateClearError` - Resume from error

== Debug Mode

Debug mode provides raw Modbus register visualization for troubleshooting and development.

=== Configuration

Enable debug mode by setting `debugMode: true` in the component configuration.

=== Debug Channels

[cols="1,1,2"]
|===
| Channel | Type | Description

| `DebugMode`
| Boolean
| Indicates debug mode is active

| `RawVoltageL1/L2/L3`
| String
| Raw voltage registers in hex (Float32 encoding)

| `RawCurrentL1/L2/L3`
| String
| Raw current registers in hex (Float32 encoding)

| `RawPower`
| String
| Raw power registers in hex (Float64 encoding)

| `RawEnergy`
| String
| Raw energy registers in hex (Float64 encoding)

| `RawState`
| String
| Raw state registers in hex

| `RawMaxCurrent`
| String
| Raw max current registers in hex
|===

=== Override Channels

These channels allow overriding hardware values with manual inputs for testing:

[cols="1,1,2"]
|===
| Channel | Type | Description

| `OverrideVoltage`
| Boolean (R/W)
| Use manual voltage values instead of hardware

| `OverrideCurrent`
| Boolean (R/W)
| Use manual current values instead of hardware

| `OverridePower`
| Boolean (R/W)
| Use manual power values instead of hardware

| `OverrideState`
| Boolean (R/W)
| Use manual state value instead of hardware

| `ManualVoltageL1/L2/L3`
| Integer (R/W)
| Manual voltage values in V

| `ManualCurrentL1/L2/L3`
| Integer (R/W)
| Manual current values in mA
|===

=== Debug HTML Page

A standalone HTML debug page is provided at `web/alfen-debug.html` for visualizing and controlling the component. It shows:

* State, power, energy summary
* Raw Modbus register values in hex format
* Manual value inputs
* Override toggles

To use:

1. Open `web/alfen-debug.html` in a browser
2. Configure the OpenEMS WebSocket URL (default: `ws://localhost:8085/websocket`)
3. Enter the component ID (default: `evseChargePoint0`)
4. Click "Connect"

== Known Limitations

* Phase switching functionality is implemented but may require additional testing
* Some registers from the official documentation are not yet implemented (e.g., temperature, session energy)
* The component assumes a standard 6A-32A current range; actual limits depend on the specific wallbox model and installation
